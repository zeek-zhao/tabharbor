# M3 导入导出与备份演练指南（issue #32）

> 状态：M3-1（#27）仍开放，等待 Chrome 手工验收。本指南覆盖**已实现**的导入、导出与备份能力，不代表 M3 完成或 v0.4.0 已发布。GitHub 备份仅做 mock 验证，**未做真实远程写入**。

## 1. 真实支持范围（核验 #27 与 `src/core/import-export.js`）

| 能力 | 支持范围 | 关键约束 |
|---|---|---|
| 导出 JSON | 全量 payload：`version/exportedAt/windows/groups/tabs/settings/trash` | `version === 1`（EXPORT_VERSION） |
| 导出 HTML | 标准 Netscape Bookmark 格式；窗口容器不导出，顶层节点并列输出 | 仅表达书签/文件夹层级 |
| 导入 JSON | 全量替换当前树 | 必须含 5 字段；`validateTree` 校验 ID 唯一、父节点存在、标签 url/title 为字符串 |
| 导入 HTML | 全量替换；`<DT><H3>/<A>` 解析，`</DL>` 出栈恢复嵌套；按 URL+标题去重 | 归入虚拟窗口「导入的书签」，启动同步再映射真实窗口 |
| 本地快照 | `manualBackup` → `saveLocalBackup`（storage key `localBackups`）+ 可选下载 | 上限 `MAX_LOCAL_BACKUPS = 20` 条滚动淘汰 |
| 恢复 | `restoreBackup(id或filename)` → `importJSON` 校验后全量恢复 | 内容损坏时拒绝：`本地备份内容损坏，无法恢复` |
| GitHub 备份 | `uploadGitHubFile`：GET sha（200/404）→ PUT 覆盖/新建；`runAutoBackup` 导出 HTML | 需可选权限 `api.github.com`；频率 every10m/30m/hourly/daily；仅此唯一出站路径 |
| 下载 | `chrome.downloads` data: URL，`saveAs: true` | downloads 只负责用户可见导出，不读取其文件内容 |

## 3. 逐步操作指南

### 3.1 导入前检查
1. 打开设置弹窗（⚙）→「备份与恢复」分类。
2. 确认当前树已导出或已有本地快照（导入是**全量替换**，原数据将被覆盖）。
3. 确认文件扩展名为 `.json`（TabHarbor 导出格式）或 `.html`（Netscape 书签）。

### 3.2 JSON 导入
1. 点击「选择文件」→ 选择 `tabharbor-m3-import.json`。
2. 确认弹窗「导入会全量替换当前树数据」→ 确定。
3. 预期：树变为「M3 演练窗口 / 演练-研究、演练-阅读」，状态栏提示 `导入完成，树数据已替换`。
4. 反向演练：选择 `tabharbor-m3-invalid.json` → 状态栏提示 `导入失败：版本不兼容…`，原树不变。

### 3.3 导出
- **JSON**：备份面板「导出 JSON」→ 下载 `tabharbor-export-*.json`（version 1，含 settings/trash）。
- **HTML**：备份面板「导出 HTML」→ 标准 Netscape 书签文件，可直接导入其他浏览器。

### 3.4 本地快照与恢复
1. 「立即备份」→ 生成可恢复快照（`localBackups` 顶部）并下载 JSON。
2. 备份列表按时间倒序展示（文件名/时间/标签数）；选择条目 →「恢复备份」→ 全量恢复并实时重渲染。
3. 快照上限 20 条：第 21 次备份后最早的快照被滚动淘汰（BDD 场景覆盖）。

### 3.5 失败处理
| 情形 | 表现 | 来源 |
|---|---|---|
| JSON 缺字段 / ID 重复 / 父节点不存在 | `导入数据缺少字段…` / `导入数据无效…`，模型不变 | `importJSON`+`validateTree` |
| 版本不兼容 | `版本不兼容：期望 v1，实际 v2` | `importJSON` |
| 备份内容损坏 | `本地备份内容损坏，无法恢复` | `restoreBackup` |
| GitHub 未授权可选权限 | `尚未授予 api.github.com 可选权限` | `uploadGitHubFile` |
| GitHub 写入失败 | `写入 GitHub 备份失败（HTTP 403）` 等 | `uploadGitHubFile` |
| 自动备份配置不完整 | `GitHub 自动备份配置不完整` | `runAutoBackup` |

### 3.6 GitHub 备份（可选，默认关闭）
1. 备份目标切到 `github` → 填 repo/branch/path/token →「授权」申请 `api.github.com` 可选权限。
2. 选择频率（10m/30m/hourly/daily）→ service-worker 注册 `auto-backup` alarm。
3. **本仓库测试全部使用 mock fetch，未执行真实远程写入**。

## 6. 边界记录

1. **不使用书签 API**：`tools/check-constraints.mjs` C05 门禁静态拒绝任何 `bookmarks.*` 调用。
2. **零出站**：除用户显式授权的 `api.github.com`（仅 backup 模块）外不发起网络请求（C11/C12 门禁）。
3. **不写真实远程备份**：GitHub 场景全部 mock fetch 实现；E2E/BDD/样例校验均无真实网络。
4. 依赖 #27 的手工 Chrome 验收；在 M3 milestone 全部 issue 关闭前不发布 v0.4.0。
