## 1. 结论摘要

| 项 | 结论 |

## 2. 为什么第一版用原创渐变

- 扩展打包第三方图片需逐张核对许可（CC0/CC-BY 及署名义务）、保留来源与作者信息，且图片体积会使包膨胀、影响审核与加载。
- 原创 CSS 渐变/图案：作者、来源、许可清晰（TabHarbor 原创 / 内置精选 / CC0），零出站、零版权争议、零CSP 图片域名问题。
- 因此第一版画廊展示 10 张原创壁纸，缩略图即 CSS 渐变本身，不发起任何网络请求。

| 来源 | 内容尺度 | 画幅 | 许可/署名 | 接入评估 |

| Wallhaven | anime / SFW 分类可筛选 | 16:9 可筛选 | 图片许可各异，作者归属需逐张核对 | **2026-11-27 接入**：API 固定 anime+SFW+16:9 参数过滤，候选带作者/来源署名；许可逐图核对仍依赖图源标注 |

评估结论（2026-11-26）：在线图库需新增主机权限、逐图版权核对、内容过滤与超时回退，超出当时「零出站红线」口径，故不接入。

2026-11-27 更新：审计报告 P1 要求提供可选网络壁纸链接列表，按以下口径接入——（1）用户点击「加载候选」时才请求，不自动轮询/预取；（2）Wallhaven 固定 anime+SFW+16:9 参数、Nekos.best 仅 neko/waifu 分类；（3）端点用协议常量拼接，C11 放行 `src/core/wallpaper-online.js`、C12 白名单 wallhaven.cc/w.wallhaven.cc/nekos.best；（4）候选仅 https、8 秒超时兜底、失败回退；（5）booru 类站点仍明确不接入。许可逐图核对依赖图源标注，残余风险已在 PRIVACY.md 留痕。

## 4. 远程图片（用户主动输入）口径

- 仅接受用户手动粘贴的 https 图片链接（`normalizeWallpaperUrl` 校验，拒绝 http 明文与一切伪协议及注入字符）。
- 链接仅存本机，不上传；可能暴露网络环境，隐私说明见 `docs/PRIVACY.md`。
- 加载：8 秒未完成或加载失败即回退内置渐变（避免长时空白与悬挂请求）。
- 远程模式清空本地图片元信息；本地图片模式清空远程 sourceUrl，二者二选一。
- 用户可填 `source_url` / `artist` 记录原图来源与作者，随配置导出。

## 5. 真机待验证项

- 远程图片的 CSP：扩展主页对 `img-src` 的限制需真机确认；若拦截则依赖失败回退渐变，不影响可用性。
- 本项标注「待验证」而非「已验证」，证据待 G1 签核人真机截图确认。
