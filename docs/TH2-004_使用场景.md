# TH2-004 · TabHarbor 使用场景说明

> 基于用户真实会话截图（单窗口 + 三层嵌套分组）整理，覆盖日常整理、跨窗口操作、恢复现场与维护。
> 对应需求轮：F 轮（用户指令 m11442 第 1/2 轮确认，规格冻结）。
> 类型判定始终只依据 `kind` 字段 + 数组归属（`src/core/levels.js` 的 `kindByMembership`），**不按标签名或链接判断类型**。

## 场景 1：导入书签后整理成树

- **目标**：把浏览器书签或本地 JSON 导入后，按主题整理为「窗口 → 分组 → 标签」的可拖拽树。
- **前置**：侧边栏/独立窗口已打开；有书签数据（`导入书签` 文件或 HTML）。
- **操作步骤**：
  1. 打开「导入」弹窗，选择书签文件/JSON，确认导入。
  2. 导入内容成为离线窗口（`windowId=null`，行首显示淡色离线点 `offline-dot`，悬停提示"未绑定浏览器窗口，双击其下标签会新建窗口"）。
  3. 把标签拖到任意窗口或分组：标签→标签排到其后；标签→分组移入末尾；标签→窗口移入首个分组（无分组则直挂）。
  4. 拖动中若目标分组折叠，悬停约 600ms 自动展开；松手即使仍折叠也照常落入。
- **预期结果**：所有导入标签可自由移动到任意窗口/分组；类型与归属始终按 `kind` + 数组一致。
- **对应需求编号**：F2（②）、F5（⑤折叠悬停）、F6（离线标记）。

## 场景 2：多窗口分工

- **目标**：把不同主题的工作分散在多个浏览器窗口，并在树里一一对应。
- **前置**：浏览器已打开多个真实窗口（每个含若干网页）。
- **操作步骤**：
  1. 启动扩展时自动执行 `pairWindows`：先按 `windowId` 精确匹配，再按"当前浏览器窗口"绑定聚焦窗口，再按标签重叠度（tabId 命中 +2 / URL +1）匹配，仍无匹配则新建模型窗口。
  2. 每个真实窗口的模型节点回填 `windowId`；模型里无对应真实窗口的节点清空失效 `windowId` 转离线。
  3. 无 http(s) 网页的真实窗口（如新标签页）跳过配对。
- **预期结果**：模型窗口与真实窗口一一对应，状态栏统计正确；"当前浏览器窗口"节点仍与真实标签严格实时同步。
- **对应需求编号**：F2（①配对）、E 轮 D 轮实时同步。

## 场景 3：跨窗口拖拽与分组↔窗口互转

- **目标**：按原始定义自由拖拽，分组与窗口双向互转且保持 id 与子树不变。
- **前置**：树中至少两个窗口/分组，含若干标签与嵌套分组。
- **操作步骤**（9 格落点矩阵，来源：已确认规格）：
  - 标签→标签：排到目标标签之后（同父）。
  - 标签→分组：移入分组末尾。
  - 标签→窗口：移入窗口首个分组；无分组则直挂窗口。
  - 分组→标签：挂到该标签所在容器。
  - 分组→分组：成为目标分组的子分组（真嵌套）。
  - 分组→窗口：转为独立窗口，插到目标窗口之后；**不立刻建真实窗口**（离线，`windowId=null`）。
  - 窗口→标签：转为该标签所在容器下的分组；若落点是直挂窗口的标签，则转为该窗口下的分组（修正历史缺陷）。
  - 窗口→分组：转为该分组下的子分组。
  - 窗口→窗口：合并——源窗口的分组与标签 reparent 到目标窗口，源窗口移除（不写回收站）。
- **预期结果**：每个方向都生效，无"拖了没反应/乱跳/对象类型错误"；互转后节点 id 与子树不变；连续来回拖拽稳定（E 轮已覆盖 4 步循环）。
- **对应需求编号**：F2（③）、F2（④）、F4（④）。

## 场景 4：双击标签回到现场

- **目标**：双击标签打开网页；若其所属窗口不存在则自动新建窗口再打开；已打开则聚焦不重复开。
- **前置**：侧边栏可见；标签有 URL。
- **操作步骤**：
  1. 双击标签 → `openLeafById` 取 `boundWindowId(m, id)` 作为 `opts.windowId`。
  2. 若 URL 已在浏览器打开（D17：只按 tabId 精确命中，无 URL 兜底）→ `tabs.update({active:true})` + `windows.update({focused:true})`，不重复新建。
  3. 未打开且 `windowId` 有效 → `tabs.create({url, windowId})`（在绑定的原窗口打开）。
  4. 未打开且 `windowId` 失效/为空 → `windows.create({url})` 新建窗口并回填 `owner.windowId`，toast 提示"已新建窗口并打开网页"。
- **预期结果**：离线窗口（如分组转出的窗口）首次双击时自动建窗并持久化绑定；之后双击均在同一窗口打开；已开标签只聚焦。
- **对应需求编号**：F2（①⑦）。

## 场景 5：三层嵌套分组（复杂会话）

- **目标**：支持截图中的三层嵌套结构（窗口 > 分组 > 分组 > 分组 > 标签）。
- **前置**：会话含多层分组，例如「大模型免费额度与免费 API」>「Console models | OpenCode」>「OpenCode Console」。
- **操作步骤**：
  1. 行首三角展开/折叠任意层级；折叠态只显示直接子节点计数。
  2. 拖拽到折叠分组悬停约 600ms 自动展开；松手仍落入。
  3. 分组行内复制按钮常显（原型 v16 / R6），可复制整树标签为 Markdown/纯文本。
- **预期结果**：任意深度嵌套可展开、可拖拽、可复制；分组标题取自页面标题但**不参与类型判定**。
- **对应需求编号**：F5（⑤）、R6、N1（类型识别）。

## 场景 6：备份与迁移

- **目标**：导出/导入完整模型（含设置、回收站），在另一台机器恢复。
- **前置**：模型含窗口、分组、标签、`windowId` 与回收站条目。
- **操作步骤**：
  1. 「导出」生成 JSON（version + settings + windows/groups/tabs + trash）。
  2. 另一实例「导入」该 JSON → `mergeAsImportedWindow` 合并为新窗口，状态栏提示"导入完成"。
  3. 导入窗口为离线状态，双击其标签时按场景 4 建窗。
- **预期结果**：结构与 `windowId` 绑定按导出内容保留；导入后标签可自由拖拽整理。
- **对应需求编号**：M3 导入导出、F2（②）。

## 场景 7：搜索定位与快捷键

- **目标**：不离开键盘快速定位/操作标签。
- **前置**：树中已有多个标签。
- **操作步骤**：搜索框输入关键词过滤；方向键在可见标签间移动选中；Enter 打开；Delete 移入回收站；Ctrl+L 定位；Ctrl+E 展开/折叠全部；Ctrl+O 打开选中标签所在分组全部标签；Ctrl+D 切主题；Ctrl+Backspace 打开回收站。
- **预期结果**：所有快捷键生效且不与输入框冲突（输入框内不触发）。
- **对应需求编号**：M1/M2 快捷键、R7/R8 对齐原型。

## 场景 8：回收站与恢复

- **目标**：误删标签/分组/窗口后原位恢复。
- **前置**：删除过至少一个节点。
- **操作步骤**：打开回收站弹窗 → 对条目点"恢复" → 节点回到删除时的原父容器与原序位（窗口节点回到原列表下标）；点"彻底删除"则永久移除。
- **预期结果**：回收站随模型持久化；恢复后 id 与子树不变；窗口合并源窗口不进回收站（按确认规格）。
- **对应需求编号**：R3（回收站原位恢复）、F2（②合并语义）。
